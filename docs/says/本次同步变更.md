# Bub 文档同步：主要代码变更摘要

本文把本次 `docs/says/` 同步背后的代码演进浓缩成一页。一句话概括：**Bub 从"Agent 返回字符串 + 渠道渲染最终文本"升级为"Agent 产出流式事件 + 渠道沿途注入渲染"，整条消息链路随之被改造。**

---

## 一、核心范式：同步字符串 → 流式事件

这是本次所有改动的主轴，其它章节都围绕它展开。

| 位置 | 旧 | 新 |
|------|----|----|
| `Agent.run()` | 返回 `str` | 返回 `AsyncStreamEvents`，强制 kwargs-only 签名 |
| Hook 接口 | `run_model` | 新增 `run_model_stream`，原 `run_model` 作为单事件回退 |
| `BubFramework._run_model` | 直接收字符串 | 消费 stream，`text`/`error` 事件分发，累积成最终 `model_output` |
| 出站 | `dispatch(envelope)` 单一路径 | 新增 `wrap_stream()` + `dispatch_output()` 双路径 |
| CLI 渲染 | 响应完成后 Rich `Panel` 一次性渲染 | `Channel.stream_events()` + Rich `Live` 按 delta 增量渲染 |

Agent 同时用 `AsyncExitStack` 延迟 `fork_tape` 的释放，保证 stream 消费完才真正关闭磁带视图，而不是 `run()` 返回就关。

---

## 二、OutboundChannelRouter 协议

`ChannelManager` 实现新协议并通过 `framework.bind_outbound_router(self)` 注入：

- `wrap_stream(message, stream)` — 按来源渠道调 `Channel.stream_events()`，让 CLI / Telegram 等在同一条事件流上注入自己的渲染。
- `dispatch_output(envelope)` — 负责流结束后的最终封装投递，保留"渲染"与"分发"的边界。
- `quit(session_id)` — 按会话取消 `_ongoing_tasks`，配合新内置工具 `,quit` 使用。

---

## 三、Hook 系统：14 个钩子 + 去隔离

- Hook 总数 12 → 14，新增 `run_model_stream` 和 `build_tape_context`。
- `HookRuntime._invoke_impl_async` 移除了 per-hook 的 `try/catch`，业务 Hook 抛出的异常会直接上抛到 `BubFramework.process_inbound` 的顶层 `try/except`，由 `notify_error` 集中观察后再 `raise`。
- `on_error` 观察者仍然保留每实现的隔离，确保诊断钩子不会互相干扰。

换句话说：**业务 Hook 不再"静默兜住"异常**，错误路径从"局部吞没 + 日志"变成"集中通知 + 继续抛"。

---

## 四、可靠性新机制

### 自动 handoff：上下文溢出的隐形回退
`Agent` 新增 `MAX_AUTO_HANDOFF_RETRIES = 1`。当 stream 的 `final` 事件命中 `_is_context_length_error` 正则时，Agent 会自动调用 `tapes.handoff(name="auto_handoff/context_overflow")` 建立锚点，然后用原 prompt 再跑一遍 —— 用户端完全无感。

### Fork 磁带的 `merge_back` 控制
- `ForkTapeStore.fork(tape, merge_back=True)` 新增参数。
- `Agent.run()` 按 `session_id.startswith("temp/")` 自动决定是否回写父磁带。
- 新工具 `subagent` 默认落在 `temp/{uuid}` 会话中，嵌套 Agent 的轨迹默认不污染父上下文。

---

## 五、工具生态：16 个内置工具

| 变化 | 工具 |
|------|------|
| 新增 | `bash.output`、`bash.kill`（配合 `bash` 的 `background=true` 模式 + `shell_manager`） |
| 新增 | `subagent`（支持 `allowed_tools` / `allowed_skills` 白名单） |
| 新增 | `quit`（通过 `OutboundChannelRouter.quit()` 关闭当前会话） |
| 改名 | `skill.load` → `skill`（函数 `skill_describe`，受 `allowed_skills` 约束） |

工具总数从"12+"变成明确的 16 个。

---

## 六、技能路径迁移

- 内置技能包从 `src/bub_skills/` 搬到 `src/skills/`。
- `skill-installer` 已经下线，内置技能只剩 `gh`、`telegram`、`skill-creator` 三个。

---

## 七、渠道层变化

- `Channel` ABC 把 `send()` 改为可选（不再是 `@abstractmethod`），新增 `stream_events()` 钩子和 `enabled` 属性。
- `ChannelMessage` 新增 `media: list[MediaItem]` 字段，多媒体改为**惰性下载**（`data_fetcher` 回调，>2MB 自动跳过）。
- `TelegramChannel`：`enabled` 绑定 `BUB_TELEGRAM_TOKEN`；构造的 `ChannelMessage.output_channel` 显式设为 `"null"`，禁用自动 `dispatch_output`，输出改由 `telegram` 技能脚本在 Agent 内部主动发送。
- `CliChannel`：`send()` 只处理 `kind="error"` 的回落，其它内容完全由 `stream_events()` 阶段的 Rich Live 渲染负责。

---

## 八、文档中修正的关键错误

- `FileTapeStore._redact_payload` 的行为被澄清：**它会直接过滤掉非文本内容**（只保留 `type=="text"` 的部分），而不是像老文档所说的"替换为 `[media]` 占位符"。
- `docs/says/04-磁带记录系统.md` 里对应的叙述已修正。

---

## 一句话回忆钩子

> **流式事件流过整条链路** — Agent 产出 `AsyncStreamEvents`，`wrap_stream` 让渠道沿途渲染，`process_inbound` 集中收束异常，`subagent` / `quit` / auto-handoff 在流的端点进一步扩展了"这一段推理要怎么收场"的语义。
